# README visual assets

The canonical PNG scenes are generated by
`obsidian-plugin/e2e/readme-captures.spec.ts` against the isolated Obsidian test
harness. The suite owns the fixture copy, framing, output dimensions, and file
names; do not replace these assets with screenshots taken from a browser-rendered
README.

From `obsidian-plugin/`, build and capture the dark release assets:

```bash
pnpm run build
CC_E2E_CAPTURE=1 CC_E2E_CAPTURE_THEME=dark pnpm exec playwright test --config=e2e/playwright.config.ts e2e/readme-captures.spec.ts
```

Set `CC_E2E_CAPTURE_DIR=/absolute/output/path` and
`CC_E2E_CAPTURE_THEME=both` to render review copies without changing tracked
assets. GIFs remain manual captures and follow the same visual rules below.

> The repo's `docs/` folder is gitignored (local scratch for plans/specs), so
> tracked images must live here in `assets/`, or in `obsidian-plugin/assets/`
> for the plugin README. Both are tracked.

## Capture settings

Apply to every asset — consistency across shots matters more than any single shot.

- **Display:** retina / 2× scale.
- **Theme:** dark, default Obsidian appearance (theme "obsidian"). Companion's chrome reads better on dark, and the README renders on both GitHub themes.
- **Vault:** deterministic demo data only. Never a real vault, and no personal note titles anywhere in frame.
- **Same fixture vocabulary for every asset** so the product looks coherent across the README, the guides, and the store.
- **Crop tight** to the relevant UI. No desktop chrome, no unrelated panes.
- **PNG:** 1600 px wide and high at most, under 1 MB. Crop chat scenes through
  the final meaningful message instead of capturing an empty full-height pane.
- **GIF:** ≤15 s, ≤8 MB, ends near its start state so the loop isn't jarring.

## The demo vault

The automated PNG suite creates a temporary, deterministic vault for every
scene and removes it after the run. `demo-vault/` at the repo root is the
gitignored manual-capture fixture for GIFs and exploratory shots.

Open it in Obsidian (*Open folder as vault*) and everything is preconfigured.
Use the dark default theme before capture. Use a non-production credential only
when a manual scene requires one; never seed credentials into the demo vault.

Contents: 45 notes across two believable clusters (a home-espresso hobby cluster
and a learning-Rust cluster with an active project), book notes, four daily notes,
a weekly review, two untriaged clippings in `Inbox/`, and a populated research
project.

`Research/Espresso Extraction/` is written in the plugin's canonical record format
— 3 sources with real SHA-256 content fingerprints, 7 evidence cards, 3 claims, 2
open questions, 1 outline. Two things are wrong **on purpose**, so the Audit and
Intelligence tabs have genuine findings to show:

- one evidence card left `proposed` and unlinked → `unreviewed-evidence` + `unused-evidence`
- one claim overstated with challenging evidence attached → a real contradiction

Regenerate it any time with `python3 demo-vault/_generate-demo-vault.py demo-vault`
(idempotent). After rebuilding the plugin, re-copy `main.js`, `manifest.json`, and
`styles.css` from `obsidian-plugin/` into
`demo-vault/.obsidian/plugins/claude-companion/`.

## Wiring a new asset

1. Add a deterministic scene to `readme-captures.spec.ts`; use product-facing
   fixture copy and a tight locator or clip.
2. Add the generated file to this table and wire it with descriptive alt text.
   Paths are relative to the consuming file: `assets/x.png` from the root README
   and `../assets/x.png` from a guide.
3. Add an appropriate dimension/aspect contract to
   `test/readmeCaptureQuality.test.ts`, then run:

   ```bash
   pnpm exec vitest run test/readmeCaptureQuality.test.ts
   pnpm run docs:verify
   CC_E2E_CAPTURE=1 CC_E2E_CAPTURE_THEME=dark pnpm exec playwright test --config=e2e/playwright.config.ts e2e/readme-captures.spec.ts
   ```
